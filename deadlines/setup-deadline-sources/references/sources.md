# 选择来源与取得订阅

## Canvas

从用户给定的学校 Canvas 域名和已登录页面进入 **Calendar → Calendar Feed**，复制现有 iCal 地址；先验证它确实返回日历，不根据学校域名拼造个人订阅地址。用户已给订阅地址时可直接试读，无需浏览器。

订阅同时含课程活动和作业；优先结合任务 URL、来源分类和用户范围识别截止，普通课程、会议及 office hours 不自动算 DDL。Canvas 的 To Do 项目不包含在该订阅中；用户需要这些项目时保留单独读取入口。实际导出的范围和条目上限也可能影响覆盖，远期查询和大量课程尤其需要核对。

官方入口与限制：[Canvas iCal feed 指南](https://community.instructure.com/en/kb/articles/662804-how-do-i-view-the-calendar-ical-feed-to-subscribe-to-an-external-calendar)。界面改变时以实际页面或最新官方说明为准。

## 已连接日历

优先使用可用的日历连接器读取用户选定日历，并保存实际发现的 ID。确定某个日历是否专门存 DDL；混合日历需要依据类别、任务字段或用户规则筛选。读取时使用时间窗口、分页及重复事件实例，不把一次返回误当完整覆盖。

服务已有连接时通常不需要再向用户索取私有订阅地址。没有连接而用户能提供 iCal／ICS 订阅时，保存订阅即可，不要求导入另一个日历服务。

## 订阅与文件

- `https://…ics`、`webcal://…` 可能直接提供订阅；`webcal` 读取时转为 HTTPS，不降级到明文 HTTP。
- 日历网页地址不等于订阅地址；返回 HTML／登录页时说明未接入，继续取得正确地址或使用已授权连接器。
- 用户只给 `.ics` 导出文件时可以先读取，记录其快照性质；需要自动更新时再取得订阅。
- 订阅失效、403 或登录要求不能靠反复猜 URL 解决。一次失败后使用现有替代来源，或请用户更新链接／完成登录。
- 完整私有订阅链接只交给用户指定来源的读取工具和本地私有配置；不交给公开搜索、第三方链接预览、截图报告或公共 Git 仓库。

试读时检查时区、日期精度、至少一个代表性任务和来源覆盖。空订阅仍可能是正常结果，但不能证明没有其他来源的 DDL。
