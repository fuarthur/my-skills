# 发现课程信息与接入工作区

从课号、学校或课程链接出发，主动查找课程事实、已发布任务与可核实的提交状态，并推荐值得配置的重复作业流程。用户提供最小线索；查资料、追踪入口和核对来源由 agent 完成。

## 1. 定位课程与已有上下文

先读目标工作区已有的 `AGENTS.md`、`README.md`、`workflows/COURSEWORK-WORKFLOW.md`、课程档案和相关任务状态。优先复用学校、学期、班型及已确认偏好；在当前任务相关范围内查找已有材料，不要求用户重新填写完整课程信息。

结合链接、官方课程目录、当期课程主页或已登录平台的课程列表，核实学校／校区、课号、正式名称、学期及有要求差异的班型。裸课号不是全局唯一标识；当前日期、搜索排名和旧学期页面不能证明用户所上的班次。上下文仍不足以区分候选时，只询问能消除歧义的最小问题，并保留候选与依据。

沿用现有课程目录；不同学校、学期或班型的要求不直接合并。没有工作区但目标位置已明确时，可用 `setup-coursework-workspace` 建骨架后接续；该 skill 不可用或写入位置尚不明确时，先完成可独立进行的只读发现并交付报告。仅在确需写入且目标仍有歧义时询问位置。

完成标准：目标班次有证据，或只剩明确的消歧问题；已有上下文、可继续部分和写入范围清楚。

## 2. 沿官方入口主动查找

先检查可用的连接器、搜索及浏览工具，按能力选择访问方式，不假定学校使用某个固定平台。将搜索结果和第三方页面作为入口线索，追踪到适用班次的官方原始来源后再确认为课程事实。

按实际课程建立并核查以下入口；来源中出现新的相关平台时继续追踪：

| 范围 | 查找内容 |
| --- | --- |
| 课程与大纲 | 当期主页、大纲、教师／班型、评分构成、课程安排、引用与 AI 政策 |
| 模块与材料 | 阅读、课件、教材、必读／选读范围和可访问资料的目录及链接 |
| 作业与测验 | 完整已发布列表、分页／筛选、各项实际题目、rubric、格式和提交入口 |
| 公告与成绩 | 要求修订、延期、本人提交／评分记录及核查时间 |
| 关联平台 | 大纲或课程页面指向的练习、项目、互评等独立平台与任务阶段 |

使用公开官网、当前用户已登录且可访问的课程平台及已有本地材料。登录由用户在正常界面完成，不收集密码、令牌或浏览器凭据。课程发现只读取课程信息；启动测验、报名、提交、发布或发送消息不属于本步骤。

取得的材料按目标工作区的通用材料检查规则处理，再用于事实摘要。搜索摘要、文字提取和截图的检查范围分别记录；访问失败不代表没有作业。检查缺口及暂停按已有规则执行，不为减少提问而绕过检查。没有工作区时，遵守当前环境的外部材料规则，报告检查限制。

先取得大纲、任务要求和资料索引；需要判断要求或执行具体任务时再取得对应正文，不将资料目录说成全文已读。保留稳定入口及实际核查时间，不保存含凭据的临时链接。

完成标准：适用入口均有已核查结果、明确不适用依据或具体缺口；分页与新发现的相关平台已处理；没有以一个平台代表整门课。

## 3. 核查任务、时间与实际状态

以当前已发布任务建立清单，用稳定标识和内容关系合并跨平台重复条目。大纲里的未来安排另列为计划；尚未发布的任务不补造题目、截止或完成状态。

逐项记录实际性质、题目／rubric 入口、提交形式，以及截止、开放、锁定时间和来源时区。保留原始时间；需要时另给用户时区的换算。公告与任务页面冲突时，查适用班型、版本和明确的修订关系，记录采用依据；无法解决的冲突保持待核实。

提交、互评、修订等阶段分别核查截止与状态。完成状态以本人的平台记录或用户明确确认作为依据；本地成果、日历条目和平台包装项完成不能代替真实提交或其余阶段的证据。区分未核查、未提交、已提交待评分和已评分，不以未读到记录推断未提交。

使用 [assets/ASSIGNMENT-INDEX.md](assets/ASSIGNMENT-INDEX.md) 建立或合并 `courses/{course-id}/assignments/INDEX.md`，保存带来源和时间的核查快照。链接已有 `STATUS.md`；本次只发现任务时，无需为每个条目创建完整制作目录。后续开始具体任务时再按通用流程建档。

完成标准：已发布任务去重且阶段齐全，截止与状态各有证据或明确未知；计划、平台快照和本地制作进度分别可辨。

## 4. 筛选重复任务并建议配置工作流

根据大纲的周期／总次数、已发布题目的实际内容和可复用步骤判断重复性，不能仅凭平台的 Assignment、Quiz 等分类或相似标题分组。

- 全学期仅一两次的类型默认按单次任务管理。名为作业、实际为期中或期末考试的条目按考试识别，一两次考试不推荐建立持久作业工作流。
- 同一项目的提案、初稿、终稿，或同一作业的提交与互评，是任务阶段，不计作多个独立重复轮次。
- 推荐项须有多个独立轮次及稳定步骤的依据。目前只发布一两次，但大纲明确安排每周或全学期多次的类型仍可推荐；将已发布数量与计划总量分别写明。
- 次数未知、仅名称相似或步骤差异较大时，列为待观察，不先注册持久流程。用户明确要求为特定低频任务配置流程时，按其实际范围处理。

在任务索引的建议表写明类型、重复依据、可复用步骤、每次仍需核实的变量，以及推荐／暂不推荐的理由。对适合的类型，明确建议使用 `configure-coursework-course` 初始化个人工作流；交接课程档案、候选类型与代表性题目入口，用户无需重述已查明的课程事实。

建议不等于启用。工作流初始化由 `configure-coursework-course` 提供“描述现有流程，由 LLM 模仿并优化”与“由 LLM 直接起草”两种方式。该 skill 不可用时，交付建议和待配置项；不伪称已调用。已有配置授权时可继续，已由配置 skill 调用本步骤时将结果交回调用方。

完成标准：每条建议有实际性质、频次及复用价值的依据；低频考试和项目阶段没有被误算为重复作业；下一步指向具体类型与配置入口。

## 5. 合并记录并交付

合并现有 `COURSE.md`，保存课程身份、官方入口、已核实事实、来源日期、冲突、覆盖缺口，以及任务索引和个人流程的链接。新档案可复用可用的 `configure-coursework-course` 课程模板；不可用时仍按这些字段建档，不因缺少其他 skill 而放弃已能完成的发现。

来源登记到 `materials/SOURCES.md`；没有具体任务时，材料检查记录在 `materials/INSPECTION.md`。保留旧版差异和仍适用的本地记录；平台快照与既有 `STATUS.md` 不一致时记录差异，不静默覆盖用户的制作进度。课程事实只更新档案和索引；个人默认只有取得相应配置依据后才更新统一工作流。

交付课程档案、任务索引及具体工作流建议的可点击路径；没有写入时交付同等内容的报告。说明已覆盖入口、未知或受阻部分、最少的用户下一步。以“已核查范围＋缺口”表述完成度；只有所有已发现的适用入口均核查后，才可声称覆盖了当前已发布任务。

完成标准：另一会话能从档案、索引、来源和检查记录继续；用户无需自行整理整套课程材料；发现、建议、已启用流程与实际提交状态没有混淆。
